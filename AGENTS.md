# Agent Coding Standards CLI

Read `CODING.md` before changing code. It contains the shared coding conventions; this file contains repository-specific context. Read `README.md` for user-facing usage. Verify current files and `package.json` rather than treating previous conversations or this handoff as immutable state.

## Purpose and Scope

This repository implements `@opendreamnet/agent-coding-standards-cli`, whose executable is `acs`. It is not the central rules repository or a Dev Container Features repository.

The default rules source is `opendreamnet/agent-coding-standards`. Consumers explicitly select profiles and generate one local `CODING.md`. Rules and CLI versions are independent: updating the executable must not silently update a consumer's pinned rules.

Updates are on demand and reviewed by a person. Automatic stack detection, per-path monorepo profiles, independent profile versions, persistent offline caching and organization-wide PR propagation are not implemented. Do not introduce them as incidental refactors.

Prebuilt releases currently target Linux x64. Development uses Node.js LTS (24+), the pnpm version declared in `package.json`, Git and Clang. UPX is required for compression. Do not claim other native platforms or private GitHub authentication have been verified solely because local fixtures pass.

## Architecture

| File                             | Responsibility                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `src/index.ts`                   | Commander registration, help, option routing and top-level error exit. Keep it a thin composition root.      |
| `src/standards/commands.ts`      | Command workflow, pinned-version checks, diffs, consent, safe file replacement and resource cleanup.         |
| `src/standards/document.ts`      | Front matter validation, ordered Markdown composition, deterministic generation and lossless YAML CST edits. |
| `src/standards/git.ts`           | Native Git transport, stable tag discovery, commit resolution, profile reads and isolated temporary storage. |
| `test/document.test.mjs`         | Schema validation, scalar styles, exact-byte preservation and composition regressions.                       |
| `test/git.test.mjs`              | Controlled subprocess failures, argument/environment safety, transport and cleanup checks.                   |
| `test/cli.test.mjs`              | End-to-end behavior using real local Git repositories and consumer-file snapshots.                           |
| `.github/workflows/release.yaml` | Tag-based Linux build, compression, artifact transfer and GitHub release publication.                        |

The runtime dependencies are `commander`, `yaml` and `diff`. Prefer these and supported platform APIs over adding another parser, Git wrapper or dependency-injection framework.

## Consumer Document Contract

Front matter reserves four properties directly at the YAML root:

| Property     | Contract                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `repository` | Canonical GitHub `owner/repo` slug. Initialization also accepts an exact HTTPS GitHub repository URL and normalizes it. |
| `version`    | Stable rules version `X.Y.Z`, without `v`; numeric components must be safe integers.                                    |
| `revision`   | Full lowercase 40-character SHA-1 of the resolved commit, not the annotated tag object.                                 |
| `profiles`   | Nonempty, ordered, unique names matching `[a-z][a-z0-9-]*`.                                                             |

The rules source publishes `vX.Y.Z` Git tags and `profiles/<name>.md`. A GitHub Release is not required. All selected profiles come from the same commit; no profiles are inferred or appended. Latest means highest numeric SemVer, not newest tag date, and prereleases are ignored.

New documents include `# Generated by acs. Project-specific exceptions belong in AGENTS.md.` inside the YAML. The body contains only selected profile content, with no automatic `# Coding Standards` heading or HTML generator banner. Preserve profile headings, code indentation and Markdown hard-break spaces; normalize line endings and blank boundaries, not significant content.

Unknown front matter is opaque and must remain intact. Validate the reserved key/value nodes rather than recursively applying CLI restrictions to all metadata. Reject duplicate YAML keys, root tags/anchors/merges and aliases, anchors or explicit tags in CLI-owned fields. Unrelated nested metadata may contain those constructs without being resolved by the CLI.

`sync` retains the original header; `update` changes only version and revision source tokens. Preserve BOM, CRLF, comments, quotes, flow style and block-scalar formatting. Keep the stable separator behavior for a closing delimiter at EOF. Do not reserialize the entire existing header through a plain object, `Document.toString()` or a front matter library.

The CST updater uses `keepSourceTokens`, `CST.setScalarValue` and `CST.stringify`. CST edits do not consult a schema, so YAML's stringifier chooses a safe style for numeric or exponent-like SHA strings. Block edits retain the original whitespace envelope and header because CST otherwise normalizes indentation, chomping and line endings. Keep these guards and regression tests when simplifying the updater.

## Command and Safety Guarantees

- `init` creates a new file, using an explicit rules version or the highest stable tag. It refuses every existing `CODING.md`, even with `--yes`.
- `sync` regenerates exactly the pinned version and commit, including after the consumer edits its selected profiles.
- `update` explicitly adopts the highest stable version, preserving profile order and refusing downgrade. It validates the existing pin before adopting another version.
- `check` never writes consumer files and exits nonzero for drift or errors. It does not accept write flags.
- Replacements show a diff and require interactive consent, or explicit `--yes`. Noninteractive runs without consent fail safely. `--dry-run` previews without writing.
- Invalid configuration, missing versions/profiles, moved tags and declined consent must not discard existing content. Keep symlink rejection, permission preservation, exclusive creation, concurrent-change checks and staging cleanup.
- The CLI writes only the consumer's `CODING.md`, apart from temporary storage. It never edits `AGENTS.md`, consumer Git state, other repositories, or performs commits, pushes or PR creation.
- Never expose credentials or unrelated YAML values in errors or previews. YAML diagnostics report offsets rather than source excerpts; existing-document diffs show generated body changes rather than arbitrary header metadata.

Keep generic temporary-storage and cleanup guarantees realistic: normal returns and errors clean up, but an externally killed process is not a successful cleanup test.

## Git Transport

`GitRules` uses native Git, not GitHub's HTTP API, in a private bare repository under `os.tmpdir()` with prefix `coding-standards-git-`. It fetches shallow tags, peels them to commits and reads regular blobs without checkout. There is no permanent cache, so regeneration and checking normally require remote access.

HTTPS is the default and uses Git credential helpers; `--transport ssh` uses the existing SSH configuration/agent. Transport is a command option, not persisted configuration. The CLI does not directly consume `GH_TOKEN` or `GITHUB_TOKEN` for rules retrieval.

Pass argument arrays without a shell. Preserve removal of repository-scoped Git environment variables and trace settings, explicit private `--git-dir`, disabled hooks/templates/maintenance and replacement objects, SHA-1 initialization, timeouts and output limits. Reject profile symlinks, directories, missing blobs, empty/binary content and oversized files. Raw Git stderr may contain credentials: capture it and return sanitized errors.

Always close the source in `finally`, including no-op, dry-run, check and failure paths. Do not use the consumer's `.git` as a download cache.

## Native Compilation Lessons

The following were observed with `scriptc` 0.2.8; revalidate before changing the relevant implementation:

- Keep `scriptc --dynamic`. Static and hybrid compilation hit YAML limitations. Successful Node tests are not proof of native compatibility.
- Commander works in the exercised CLI paths. Cleye was rejected because `terminal-columns` eagerly requires `Intl.Segmenter`, which the embedded runtime lacks; disabling help did not avoid the import failure.
- `execFileSync` supports the environment, timeout and stderr-capture options needed by the Git transport. The callback form of `execFile` did not support those options in native compilation. The Promise interface does not make the internal Git calls asynchronous.
- Keep `process.exit(1)` for top-level failures: `process.exitCode` did not produce the required nonzero native exit status.
- Some exported YAML metadata shapes require explicit `null`/`undefined` checks. Preserve the strict root-map guards rather than mechanically replacing them with loose equality.
- Foreign generator materialization, complex exported scalar intersections and some iterator APIs caused compiler blockers. The current CST implementation uses scalar source tokens and ordinary indexed loops; do not revive a Parser/Composer generator pipeline without native validation.
- A `.o` file proves object generation, not linking or executable behavior. Validate the actual binary when changing runtime behavior or dependency boundaries.

Warm pnpm installs can restore `scriptc`'s cached postinstall output without restoring executable permissions on helpers in its sibling platform package, causing `SC3004: TypeScript server startup: Permission denied`. The official postinstall fixes these permissions. Keep `allowBuilds.scriptc: true` in `pnpm-workspace.yaml` and run `pnpm rebuild scriptc` after cached installs, as the release workflow does. Do not replace this with blanket recursive chmod or disable package security policies.

## Development and Validation

Use the repository's pnpm scripts and lockfile. Do not run release, deploy, interactive upgrades, commits or pushes merely to validate a change.

```bash
pnpm install --frozen-lockfile
pnpm rebuild scriptc
pnpm dev --help
pnpm typecheck
pnpm lint
pnpm prettier:check
pnpm test
pnpm test:native
```

`pnpm dev` runs TypeScript directly with Node; `scriptc run` is not a substitute for passing arbitrary CLI arguments. `pnpm test:native` builds `build/acs` and sets `CLI_TEST_BINARY` for the same test suite. That variable switches CLI integration execution; document and Git unit tests still execute under Node.

When changing native behavior or release packaging, also validate a fresh compressed executable:

```bash
pnpm build
pnpm build:compress
upx --test build/acs
CLI_TEST_BINARY=./build/acs pnpm test
```

Integration fixtures create real temporary commits, tags and remotes, redirect URLs through isolated Git configuration, and snapshot consumer `.git` and unrelated files. Keep them offline from real GitHub and independent of developer credentials. Annotated/moved tags, SemVer ordering, invalid configuration, no-write paths, BOM/Unicode/CRLF/block scalars, EOF, secret-safe previews, symlinks, permissions and concurrent edits are important regression areas. Linux pseudo-terminal tests use `script` and may skip when unavailable; report skips rather than implying full coverage.

Before completion, manually review `CODING.md` compliance after formatting. Pay particular attention to multiline sibling separation, named function/method JSDoc and prose-comment layout; the automated tools do not enforce all of these rules. Preserve unrelated worktree changes and state which checks actually ran.

## Releases

The current workflow builds/publishes on creation of stable `vX.Y.Z` CLI tags. Updates/deletions skip the build job. Manual dispatch must select a tag. Version metadata comes from that tag, not from `package.json`; ordinary checkout uses the event defaults without redundant ref/SHA forwarding steps.

CI installs the toolchain, rebuilds `scriptc`, checks types/lint/format, builds and compresses `acs`, and tests the compressed binary. The release job downloads `release-linux-x64` into its own `artifacts/` directory, generates `SHA256SUMS.txt`, verifies that the existing tag still matches `github.sha`, and publishes using `GITHUB_TOKEN` as `github-actions[bot]`. Build permissions are read-only; publication has `contents: write`. Do not reintroduce automatic tag creation or version bumps into this workflow.

Changing a workflow locally does not change an old run or an existing immutable tag. A new release execution must use a tag containing the intended workflow changes. Keep `README.md` compact and update user-facing help when flags or document contracts change; keep shared coding rules in `CODING.md`, not duplicated here.
